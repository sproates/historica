# Static-page pilot

All 230 history routes are generated by Astro. The pilot lets us check the static pages against the existing explorer before replacing its interaction controller.

The build reads the canonical Markdown and YAML histories through the existing adapter. The initial comparisons and regional lanes use the same model functions as the browser. Map fitting is now a shared TypeScript function, so the generated map and interactive map start with the same bounds. Research references and existing review qualifications are retained.

`src/pages/[type]/[id].astro` uses a shared layout and components for the introduction, comparisons, timeline, map, detail rows and evidence. The explorer component retains the current control IDs and surrounding markup. It deliberately keeps the existing CSS and browser controller during this stage. Default content is present in the response HTML; saved query settings are still applied by the controller after loading.

## Running it

- `npm run test:static` builds the pilot and checks its content, source links, fitted geography and controller hooks.
- `npm run preview:static` refreshes the persistent Wi-Fi preview and overlays all history pages.
- `npm run preview:sync` restores the ordinary prototype preview.

The pilot is excluded from production and Pages packaging. Its output is a page overlay that depends on the existing assets, not an independently deployable artifact. It is marked noindex. The repository remains private and ASO remains live.

The current interaction controller still fetches the full collection. Default pages now retain the generated content while controls attach. Customised content bookmarks and subsequent interactions still rebuild displayed regions through the existing renderer. Astro templates and their page models are now strictly checked before the static build.

## Strict static-page checks

`npm run check:static` checks Astro templates and TypeScript through `tsconfig.astro.json`, with strict null checks, unchecked-index protection and exact optional properties. `build:static` runs this gate before generating HTML, so the existing CI static-page job also enforces it. The normal TypeScript compilation remains separate because it emits the compatibility browser modules.

`src/presentation/history-page.ts` constructs the typed page model. The filesystem adapter validates historical records, while the page model checks the JSON boundaries for evidence and geography. Checked statements resolve their source references before reaching templates. Missing coordinates retain their research references without producing a map marker.

The Astro checker currently declares support for TypeScript 5 and 6. TypeScript is therefore pinned to 6.0.3, with Node unchanged at 26, rather than forcing an unsupported dependency combination. The generated Alexander HTML is byte-for-byte identical to the previous pilot. A deliberately invalid component prop was rejected by the new checker; the temporary probe was then removed.

## Reuse the generated map

Static pages now reuse the world paths already present in their HTML. They fetch a 28,799-byte regional geometry file instead of the 2,294,670-byte country dataset. Coordinates and outlines are unchanged. These are uncompressed file sizes, not measured transfer sizes; the generated HTML still contains the base map. Legacy pages without embedded paths retain the full-data fallback.

The regional file is regenerated from the existing country source during content builds and checked for drift in CI. Tests verify the requested asset, exact regional geometry, preserved base paths and legacy fallback. Browser checks cover switching to Britain and Ireland, fitting its area and reloading. History and evidence downloads remain unchanged.

## Compact browser evidence

History pages now request `browser-evidence.json`, a generated projection containing the claim, source, passage and chronology fields used by the explorer. The full reviewed evidence file and authored research remain intact, and the coverage page continues to use the full file. The projection retains every claim and citation identity, including provisional claims.

The uncompressed payload falls from 753,753 to 302,124 bytes. Tests compare checked statements and citations for all 230 histories and age estimates across every recorded life, and verify deterministic output and reference integrity. This is a smaller shared payload, not yet per-page or on-demand evidence loading. CI checks that the generated projection is current.
