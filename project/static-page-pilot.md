# Static-page pilot

All 230 history routes are generated by Astro. The pilot lets us check the static pages against the existing explorer before replacing its interaction controller.

The build reads the canonical Markdown and YAML histories through the existing adapter. The initial comparisons and regional lanes use the same model functions as the browser. Map fitting is now a shared TypeScript function, so the generated map and interactive map start with the same bounds. Research references and existing review qualifications are retained.

`src/pages/[type]/[id].astro` uses a shared layout and components for the introduction, comparisons, timeline, map, detail rows and evidence. The explorer component retains the current control IDs and surrounding markup. It deliberately keeps the existing CSS and browser controller during this stage. Default content is present in the response HTML; saved query settings are still applied by the controller after loading.

## Running it

- `npm run test:static` builds the pilot and checks its content, source links, fitted geography and controller hooks.
- `npm run preview:static` refreshes the persistent Wi-Fi preview and overlays all history pages.
- `npm run preview:sync` restores the ordinary prototype preview.

The pilot is excluded from production and Pages packaging. Its output is a page overlay that depends on the existing assets, not an independently deployable artifact. It is marked noindex. The repository remains private and ASO remains live.

The current interaction controller still fetches the full collection. Default pages now retain the generated content while controls attach. Customised content bookmarks and subsequent interactions still rebuild displayed regions through the existing renderer. Astro templates and their page models are now strictly checked before the static build.

## Strict static-page checks

`npm run check:static` checks Astro templates and TypeScript through `tsconfig.astro.json`, with strict null checks, unchecked-index protection and exact optional properties. `build:static` runs this gate before generating HTML, so the existing CI static-page job also enforces it. The normal TypeScript compilation remains separate because it emits the compatibility browser modules.

`src/presentation/history-page.ts` constructs the typed page model. The filesystem adapter validates historical records, while the page model checks the JSON boundaries for evidence and geography. Checked statements resolve their source references before reaching templates. Missing coordinates retain their research references without producing a map marker.

The Astro checker currently declares support for TypeScript 5 and 6. TypeScript is therefore pinned to 6.0.3, with Node unchanged at 26, rather than forcing an unsupported dependency combination. The generated Alexander HTML is byte-for-byte identical to the previous pilot. A deliberately invalid component prop was rejected by the new checker; the temporary probe was then removed.

## Evidence loaded by history

The explorer now loads `data/evidence/<id>.json` for the selected history and a shared 8,656-byte chronology index. Tests cover every history’s statements and citations, chronology parity, request ordering, failures, caching and whole-period navigation. Browser checks cover Socrates to Stonehenge and Back.

## Incremental local static builds

`npm run build:static:incremental` writes a separate local output under `release/static-incremental/`. It fingerprints each complete page model and shared code/configuration inputs. Templates no longer receive the whole collection: place labels and comparison regions are explicit model fields, so dependency changes cannot hide behind template lookups. Geography is a shared dependency. Models are still recalculated for all histories; only affected HTML pages are rendered and checked.

Missing or changed HTML is rebuilt even when its inputs match the manifest. Selected routes build in a temporary directory and undergo checks for controller hooks, canonical paths, dates and source links before replacing outputs. Removed routes are pruned only after a successful build. Changes to shared code or configuration rebuild all pages and run Astro checks. Unchanged pages retain their timestamps. `npm run preview:static:incremental` refreshes the existing Wi-Fi service with that output; it does not publish.

Verification included a no-change run (230 reused), a temporary Socrates evidence edit (one rebuilt, 229 reused), restoration, and byte-for-byte comparison of all 230 pages with a clean build. Planner tests cover shared changes, changed models, missing/corrupt output, additions, removals and related-page dependencies. The ordinary full-build command remains available. CI cache reuse is described below.

## Verified cache reuse in CI

CI now restores the incremental output and runs `scripts/verify-static-incremental.mjs`. It checks the build manifest against a separate successful-test record. Cold caches, shared code changes and static test changes run the full static suite. Content changes run tests for affected histories; unchanged pages retain their verified record. A failed test run cannot advance that record. Model, data and controller tests still run for every site change, and internal documentation changes still skip site work.

Only successful main-branch push jobs save caches. PRs and manual runs may restore them but do not publish shared caches. Cache actions are pinned to a commit; missing or corrupt output falls back to rebuilding. Local verification covered a cold run (230 pages checked), a warm run (zero pages rechecked), and a temporary Socrates evidence change (one checked, 229 reused). End-to-end CI verification passed in run 45200730361 after the main-branch cache was saved: all 230 pages and their static test records were reused. The verify job took 49 seconds and deployment was skipped.

## Standalone static package

`npm run package:static` generates current content and coverage, builds and verifies affected Astro pages, then packages those pages with the existing shared assets and ancillary pages in `release/static-site/`. It defaults to the `/historica/` staging mount and disables indexing. No hosting configuration or deployment is changed. The existing CI artifact remains on the ordinary builder until the new package has been reviewed.

The packager accepts `--static-source` for a complete Astro route tree. It reads and checks every expected history before replacing the previous package, omits duplicate legacy `pages/` HTML, and records the renderer and file checksums in the release manifest. Missing or mismatched history pages fail packaging instead of silently falling back to the prototype. Tests cover route mounting, shared assets, indexing, source/output separation and incomplete input. Home, About and coverage still use their existing generation.

## Generated browser output

`web/generated/` is ignored and no longer committed. `scripts/build-client.mjs` clears this owned output directory, compiles TypeScript, then generates the prototype module from authored content. The evidence builder uses the typed assembly function directly, removing its dependency on a pre-existing generated prototype module.

Start commands, preview installation and coverage generation prepare browser output before using it. Existing test, preview and package commands already build it. CI builds from source; it no longer compares generated browser modules with Git. Other generated data and legacy HTML remain tracked for now. This change does not relocate public asset URLs or publish a release.
