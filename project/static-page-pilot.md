# Alexander static-page pilot

Alexander is the first route generated by Astro. The pilot lets us check the static page against the existing explorer before replacing its interaction controller or extending generation to the whole collection.

The build reads the canonical Markdown and YAML histories through the existing adapter. The initial comparisons and regional lanes use the same model functions as the browser. Map fitting is now a shared TypeScript function, so the generated map and interactive map start with the same bounds. Research references and existing review qualifications are retained.

`src/pages/person/alexander.astro` uses a shared layout and components for the introduction, comparisons, timeline, map, detail rows and evidence. The explorer component retains the current control IDs and surrounding markup. It deliberately keeps the existing CSS and browser controller during this stage. Default content is present in the response HTML; saved query settings are still applied by the controller after loading.

## Running it

- `npm run test:static` builds the pilot and checks its content, source links, fitted geography and controller hooks.
- `npm run preview:static` refreshes the persistent Wi-Fi preview and replaces only its Alexander page with the pilot output.
- `npm run preview:sync` restores the ordinary prototype preview.

The pilot is excluded from production and Pages packaging. Its output is a page overlay that depends on the existing assets, not an independently deployable artifact. It is marked noindex. The repository remains private and ASO remains live.

The current interaction controller still fetches the full collection and rebuilds the displayed regions. Static generation alone doesn't fix that. Astro templates compile during the build but do not yet have a separate strict template type-checking step; the migrated domain TypeScript does.

## Checks and next work

The first slice includes static response checks and the existing model suite. Browser checks cover Alexander to Philip, browser Back, reload, comparison scale and a bookmarked date window, with phone and desktop layouts inspected. JavaScript-free reading is checked in generated HTML; native disclosure sections retain sources and caveats, and a noscript section provides links to connected histories.

Next, introduce typed page view models and separate the interaction controllers from the rendering templates. Preserve bookmarks before extending the static route set. Remove duplicate template paths as that replacement lands. Customised bookmarks can still show the default state briefly while the existing controller loads, and this pilot makes no incremental-build claim.

## Controls and bookmark extraction

Focus selection, date windows and URL encoding now live in strict TypeScript under `src/state/`. The public browser modules remain small adapters so existing routes and import paths keep working, including the GitHub project prefix. A migration comparison confirmed identical results for 460 default and customised bookmarks across all 230 histories.

The date, year and filter controls now attach through `src/controllers/explorer-controls.ts`. They read current state and report changes through callbacks; they don't render the page or write browser history. The main explorer still owns rendering, browser history and map interaction. This is a first separation of controls, not a completed replacement of the controller.

Control tests cover place-window preservation, filter and bookmark round trips, stepping from BCE to CE without year zero, zoom and detaching handlers. Browser checks cover zoom, fitting the lifespan, filtering, selecting a year and restoring those settings after reload.

Search ranking is now typed in `src/domain/search.ts`. Search input, keyboard navigation and result selection live in `src/controllers/search-controls.ts`; people selection, duplicate handling, scale controls and reset live in `src/controllers/comparison-controls.ts`. These controllers use callbacks to request focus or comparison changes. They preserve the existing labels and markup, and can detach their listeners. Search results still use the whole collection, independently of the visible period.

Tests cover keyboard focus, selection, clearing, escaping authored text, incomplete and duplicate people choices, reset and listener cleanup. Browser checks also confirm that a Socrates/Plato comparison survives reload and returns to the suggested comparison after reset.

Timeline input and focus navigation now use separate typed controllers. The timeline controller handles year selection on the date axis, pointer capture and cancellation, regional lane expansion and the jump-to-timeline link. The navigation controller handles focus entries, regional filters, the focus picker, whole-period selection, expanded context and Back through callbacks. Focus transitions and browser history are still coordinated by the existing app.

Checks cover year-zero avoidance, current-window dragging, capture cleanup, replacement-button focus after lane rendering, journey filters and disabled entries. Browser checks confirm year selection, lane expansion, changing focus to Egypt while retaining the window, Back and restoration after reload.
